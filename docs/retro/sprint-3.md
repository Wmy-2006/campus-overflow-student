## 1. 匿名卡片汇总（每位成员贴 3 张，本栏匿名归并）

### ✅ Start（开始做 —— 值得尝试的新做法）
1. 全员从个人仓库切换到老师指定的组织仓库统一开发，规范"分支 + PR + CI"流程。
2. 每次 PR 合并前先确认 CI 转绿，再由 reviewer 合并，避免"先合后修"。
3. 开始前统一核对每位成员的 git 身份（name / email），避免贡献统计与认领丢失。

### 🛑 Stop（停止做 —— 阻碍/低效的做法）
1. 不要再在个人仓库各自开分支、再手工迁移到组织仓库（重复劳动、易漏文件）。
2. 不要再出现提交作者邮箱配置错误（双 @ 导致 GitHub 无法认领、贡献统计丢失）。
3. 不要让 PR 积压到 Sprint 尾才合并，尽量分任务及时 review。

### 🔄 Continue（继续做 —— 行之有效的做法）
1. 保持领域层 / 应用层分层，并用 ADR 记录关键决策（ADR-009 声誉规则集中 + 事件联动）。
2. 保持 Gherkin 验收用例驱动开发（T13 用验收用例补投票对问题分数的调整与事件透传）。
3. 持续用 GitHub 看板跟踪 Sprint 进度，任务卡片按时从 To Do 移入 Done。
